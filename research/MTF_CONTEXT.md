# Мультитаймфреймный анализ: два варианта проверены как фильтр, оба не дали edge — оставлен как контекст

Запрос: превратить бота в профессиональную мультитаймфреймную систему
(D1 задаёт тренд → 4H формирует сетап → 1H подтверждает вход — классическая
Elder's Triple Screen). Сначала честно проверили саму гипотезу, прежде чем
строить вокруг неё архитектуру.

## Вариант 1: EMA-тренд на D1 + RSI-разворот на H1

Методология: реальный движок сигналов бота (`computeSignal`, 4H) как есть.
Дополнительно на каждую сделку — согласен ли тренд по EMA21/50 на дневных
барах (агрегированы из тех же часовых свечей), и был ли на H1 прямо перед
входом разворот RSI из зоны перекупленности/перепроданности.

20 пар, 1613 сделок движка, train/test по времени + негативный контроль
(перемешивание флагов).

```
                                полная история
база (все сделки)                  : WR=22.7%  avgR=-0.163
+ 1D согласен с направлением       : WR=22.6%  avgR=-0.144  (n=1193, почти без изменений)
+ 1H RSI-разворот                  : WR=14.3%  avgR=-0.565  (n=77,  заметно хуже)
+ оба сразу (все 3 TF)             : WR=15.9%  avgR=-0.489  (n=63,  хуже базы)
```

Train: avgR −0.645 (n=46). Test: avgR −0.067 (n=17). Негативный контроль
(5 прогонов со случайными флагами той же частоты) дал разброс avgR от
−0.532 до +0.067 — то есть результат «все три TF совпали» статистически
неотличим от случайного выбора ~60 сделок из того же пула. 1H-триггер по
RSI-развороту в этой реализации сам по себе выглядит как антипаттерн
(похоже на покупку в падающем ноже).

## Вариант 2: структура (HH/HL) на D1 + пробой локального экстремума на H1

Та же методология, другая реализация обеих ступеней: тренд на D1 — по
структуре свинг-максимумов/минимумов (то же правило, что уже использует
`computeSignal` на 4H, перенесено на дневной таймфрейм), триггер на H1 —
пробой локального 6-часового экстремума в направлении сделки.

```
                                полная история
база (все сделки)                  : WR=22.7%  avgR=-0.163
+ 1D структура согласна            : WR=20.9%  avgR=-0.208  (n=726,  хуже базы)
+ 1H пробой локального экстремума  : WR=20.3%  avgR=-0.290  (n=664,  хуже базы)
+ оба сразу (все 3 TF)             : WR=19.7%  avgR=-0.262  (n=274,  хуже базы)
```

Train: avgR −0.313 (n=189). Test: avgR −0.150 (n=85, примерно как база
−0.156 — то есть фильтр вообще ничего не изменил на test). Негативный
контроль дал разброс avgR от −0.337 до −0.071 на выборках сравнимого
размера — фактический результат фильтра (−0.262 на полной истории) лежит
внутри этого шумового диапазона.

## Итог по обеим попыткам

Ни EMA-, ни структурная реализация тренд-фильтра на D1 не добавляет
измеримой ценности — что логично: 4H-движок уже сам построен на структуре
и EMA, и дневной тренд в большинстве случаев просто повторяет то же самое
на более грубом масштабе (мало независимой информации). Оба варианта
1H-триггера (RSI-разворот, пробой экстремума) на полной истории и train
только ухудшали результат, а на test — либо тоже хуже, либо неотличимо от
шума. Это пятый подряд честно измеренный отрицательный результат в этом
репозитории (20 подтверждений → 30 подтверждений → ML-классификатор →
MTF-вариант 1 → MTF-вариант 2).

## Решение: мультитаймфреймная картина остаётся, но как контекст, не фильтр

По итогам разговора с владельцем — прекратить поиск edge в этом направлении
и превратить D1/4H/1H в **информационную панель** для трейдера (аналог
«Market Explanation Engine» из исходного запроса), без утверждения, что
согласие таймфреймов увеличивает винрейт или прибыльность — потому что
измерено обратное.

Реализовано в `index.html`:
- `structDirection(k, dep)` — структурное направление (HH/HL vs LH/LL) на
  произвольном таймфрейме, отдельная функция от `computeSignal()`, чтобы
  не трогать уже проверенную логику генерации сделок.
- `h1Momentum(k)` — текущий тренд по EMA21/50 и пробой локального
  6-часового экстремума на H1, чисто описательно.
- `mtfContext(sym, dir4h)` / `mtfBlockHtml(sym, sg)` — собирают картину
  D1/4H/H1 и рендерят блок «МУЛЬТИТАЙМФРЕЙМНАЯ КАРТИНА» в разборе сигнала
  (`openSignalDetail`), с явной пометкой в самом блоке: совпадение
  таймфреймов проверено и не увеличивает винрейт — не повод отменять
  собственное управление риском.
- D1/H1 свечи подгружаются лениво (`loadKlines`) только при открытии
  разбора конкретного сигнала — блок сначала показывает «Загружаю…», потом
  дорисовывается без перерисовки всего листа.

Код проверки: `research/ml/mtf_test.mjs` (вариант 1), `research/ml/mtf_test2.mjs`
(вариант 2).
