# MIE 1.0.0 — результаты бэктеста

**Короткий ответ: движок собран, работает и хорошо объясняет рынок — но зарабатывать он не умеет.
На истории он теряет деньги, причём теряет ХУЖЕ, чем подбрасывание монетки на тех же точках входа.
70% винрейта нет. Требование пункта 37 задания — «если backtest плохой, скажи прямо» — выполняется здесь.**

Дата прогона: 2026-09-01. Движок: `mie.js` v1.0.0 (тот же файл, что грузится в приложении).
Скрипты: `research/ml/mie_backtest.mjs`, `research/ml/mie_smoke.mjs`, `research/ml/mie.test.mjs`.

---

## 1. Условия прогона

| | |
|---|---|
| Данные | 20 пар USDT, 4h (агрегировано из 1h), ~2290 баров на пару |
| Период | 2025-08 … 2026-08 (≈12,5 месяцев) |
| Вход | по **открытию следующего бара** после сигнала (сигнал знает только закрытие текущего) |
| Комиссия | 0,05% тейкер с каждой стороны |
| Проскальзывание | 0,02% на вход + 0,02% на выход |
| Риск на сделку | 1% капитала, компаундинг |
| Стоп и тейк в одном баре | считается **стоп** (всегда в худшую сторону) |
| Незакрытые сделки | закрываются по последней цене, **не выбрасываются** |

Последние два пункта — не формальность. Выброс «ещё не закрытых» сделок и оптимистичное
разрешение неоднозначного бара — два самых распространённых способа нарисовать себе винрейт.
Ранее в этом репозитории первая ошибка уже один раз превратила убыточный результат в прибыльный
(см. `research/BACKTEST.md`).

## 2. Главный результат

### Все сделки (n = 448)

| Метрика | Значение |
|---|---|
| Win rate | **45,5%** |
| Средний R | **−0,1694** ± 0,0492 (t = **−3,44**) |
| Profit factor | 0,70 |
| Средняя прибыль / убыток | +0,874R / −1,042R |
| Матожидание | −0,1694R на сделку |
| Чистый результат | **−54,3%** ($10 000 → $4 566) |
| CAGR | −52,9% |
| Макс. просадка | 56,8% |
| Sharpe / Sortino / Calmar | −3,38 / −4,57 / −0,93 |
| Recovery factor | −0,96 |
| Макс. убытков подряд | 6 |
| Средний MAE / MFE | 1,04R / 1,25R |
| Среднее время в позиции | 5,6 бара 4h (≈22 часа) |
| Выходы | стоп 382, тейк 65, по последней цене 1 |

t = −3,44 означает, что убыток **не случайность**: вероятность получить такой результат при
нулевом матожидании — меньше 0,1%.

### Издержки

Средний R **до** издержек: −0,1275. **После**: −0,1694.
Издержки съедают 0,042R на сделку, но они **не причина убытка** — движок убыточен и без них.

## 3. Негативные контроли — самое важное

Вопрос: движок вообще что-нибудь знает о направлении, или это шум?
Три контроля на **тех же точках входа и с тем же расстоянием стопа**, менялось только направление.

| Вариант | n | Win rate | Средний R | t |
|---|---|---|---|---|
| **Движок как есть** | 448 | 45,5% | **−0,1694** ± 0,049 | −3,44 |
| Случайная сторона (seed 1) | 481 | 53,4% | +0,0271 ± 0,050 | +0,54 |
| Случайная сторона (seed 2) | 476 | 48,1% | −0,0812 ± 0,050 | −1,62 |
| **Инверсия направления движка** | 537 | 53,3% | **+0,0628** ± 0,049 | +1,29 |
| Полностью случайные входы (3 seed'а) | ~857 | 47–51% | −0,041 / −0,085 / −0,092 | — |

Читается это так:

- **Монетка на точках движка даёт ≈ −0,03R** — ровно столько, сколько стоят издержки.
  Это и есть «нулевой edge»: то, что должно получаться, когда информации нет.
- **Движок даёт −0,169R** — это на ~0,14R (примерно 2,8σ) ХУЖЕ монетки.
- **Инверсия даёт +0,063R.**

Вывод, который надо назвать честно: **направление, которое выбирает движок, несёт реальную
информацию, но со ЗНАКОМ МИНУС.** Это не «нет сигнала» — это систематически неверный сигнал.
Монетка сидит ровно там, где предсказывают издержки, а движок значимо ниже её.

### Почему так получается

Механизм видно в разбивке по сетапам: 348 из 448 сделок — `TREND_CONTINUATION`.
Движок построен на подтверждениях: он входит, когда тренд, структура, моментум, объём и
старший ТФ согласны друг с другом. На 4h крипте момент, когда согласны ВСЕ, — это, как правило,
конец импульса, а не его начало. Чем больше подтверждений требуется, тем позже вход.
Логика «жду 20 из 30 подтверждений» покупает не движение, а его хвост.

Это согласуется с пятью предыдущими проверками в этом репозитории (`BACKTEST.md`,
`ML_TRAINING.md`, `CONFIRMATIONS_30.md`, `MTF_CONTEXT.md`): ужесточение фильтров каждый раз
ухудшало результат, а не улучшало.

## 4. Walk-forward

Четыре последовательных окна по времени — проверка, держится ли результат или это один плохой участок.

| Окно | Период | n | WR | Средний R | t |
|---|---|---|---|---|---|
| 1 | 2025-08 … 2025-11 | 111 | 50,5% | +0,0116 | +0,11 |
| 2 | 2025-11 … 2026-02 | 164 | 42,7% | −0,2630 | −3,41 |

| 4 | 2026-05 … 2026-08 | 86 | 50,0% | −0,1087 | −0,98 |

Убыточны 3 окна из 4, два из них — статистически значимо. Ни одного значимо прибыльного окна.

**Отдельное предупреждение о том, как НЕ надо читать эти две таблицы.**
`LIQUIDITY_SWEEP` (n=16, PF 1,19) и `BREAKDOWN` (n=7, PF 1,65) выглядят прибыльными.
При таких n это ничего не значит: 16 сделок со средним R 0,073 при разбросе ~1R — это
стандартная ошибка около 0,25, то есть результат неотличим от нуля. Плюс мы смотрим на
десяток срезов сразу, и один-два «хороших» появятся там просто по правилам арифметики
(проблема множественных сравнений). Оставлять только эти сетапы = подгонка под этот
конкретный отрезок истории. Это ровно та ошибка, от которой предостерегает п. 34 задания.

## 7. Разрыв между планом и фактом по R:R

Требование было: R:R от 1:2 до 1:10.

- **Плановый R:R** движок выдаёт правильный: медиана 2,10, p95 6,19 — в заданном коридоре.
- **Фактический** R:R: средняя прибыль 0,874R против среднего убытка 1,042R, то есть **0,84 : 1**.

Причина — схема сопровождения позиции: 40% фиксируется на 1R, стоп переводится в безубыток,
дальше трейлинг. Стоп в безубытке выбивается очень часто (382 выхода по стопу против 65 по тейку),
и до 2R/3R доходят единицы. То есть красивый плановый R:R 1:2+ до результата не доживает.
Средний MFE 1,25R при среднем MAE 1,04R говорит о том же: сделки почти всегда сначала уходят
против входа примерно на величину стопа.

Это отдельная проблема, и она **не** решается натягиванием целей подальше: при 45% винрейта
более дальние цели просто снизят долю достигнутых тейков.

## 8. Что из этого следует

**Чего делать нельзя:**

1. Нельзя включать этот движок на автоторговлю. Ожидание −0,17R на сделку — это
   гарантированный слив, а не «неудачный период».
2. Нельзя просто перевернуть знак и объявить, что стратегия найдена. Инверсия даёт t = 1,29 —
   это НЕ значимо (нужно ≥ 2). Кроме того, стопы и цели строились под исходное направление;
   перевёрнутая система требует своей геометрии, а не зеркала. Взять инверсию как готовую
   стратегию = подгонка под ту же выборку, на которой она найдена.
3. Нельзя оставлять только «прибыльные» сетапы из таблиц выше — см. предупреждение в § 6.

**Что реально стоит проверять дальше** (в порядке ожидаемой отдачи):

1. **Fade вместо continuation.** Единственный сигнал в данных, у которого есть направление, —
   это то, что подтверждённое продолжение тренда на 4h работает в минус. Правильная проверка:
   строить mean-reversion сетап ЧЕСТНО — со своими стопами (за экстремум импульса), своими
   целями (возврат к VWAP/POC/средней) и своими условиями входа, — а затем валидировать на
   ОТЛОЖЕННОЙ выборке, которая в этом анализе не участвовала.
2. **Меньше подтверждений, не больше.** Все проверки в репозитории показывают одно и то же:
   ужесточение фильтра ухудшает результат. Стоит проверить обратную гипотезу — 3–5 условий
   вместо 20 из 30.
3. **Другой горизонт.** 4h с удержанием ~22 часа — зона, где издержки (0,042R) заметны, а
   информации мало. Дневной таймфрейм с удержанием в неделях даёт другое соотношение.
4. **Другие данные.** На публичном OHLCV этих 20 пар edge не найден шесть раз подряд.
   Funding rate, open interest, стакан, ликвидации — это данные, которых у движка сейчас нет
   (модуль ликвидности честно возвращает `available: false`). Логично искать edge там, где
   информация есть, а не там, где её уже шесть раз не нашли.

## 9. Что движок всё-таки даёт

Убыточный сигнал — не значит бесполезный код. Что в нём объективно есть и работает:

- **38 юнит-тестов проходят**, включая проверки причинности: дописывание будущих свечей не
  меняет решение на прошлом баре.
- **NO-TRADE как основной режим**: 97,7% баров движок отказывается торговать и объясняет, почему.
  Топ причин: качество сетапа ниже порога, плохой R:R, старший ТФ против, объём ниже нормы.
- **Никаких выдуманных данных**: нет стакана — `available: false`, а не правдоподобные числа.
- **Объяснение решения человеческим языком**: причины, риски, режим, структура, уровни.
- **Риск-менеджмент**, который не зависит от качества сигнала: размер от расстояния до стопа,
  запрет мартингейла, дневной стоп, лимит позиций в одну сторону, проверка ликвидации.
- **Честная инфраструктура измерения** — то, чем этот результат и был получен.

Поэтому в приложении MIE включён **как аналитическая панель**, а не как источник сделок:
он показывает разбор рынка и причины отказа, и рядом с ним стоят эти самые цифры бэктеста.
Автоторговли на нём нет и не будет, пока не найдётся сетап с положительным матожиданием на
отложенной выборке.

## 10. Воспроизведение

```bash
node research/ml/mie.test.mjs                        # 38 юнит-тестов
node research/ml/mie_smoke.mjs                       # распределения на реальных данных
node research/ml/mie_backtest.mjs                    # основной прогон
node research/ml/mie_backtest.mjs --invert           # инверсия направления
node research/ml/mie_backtest.mjs --randside --seed=1 # случайная сторона
node research/ml/mie_backtest.mjs --random --seed=1  # полностью случайные входы
```

Данные — часовые свечи 20 пар в `/tmp/bt/*.json` (скачиваются `research/ml/../../bt/fetch.mjs`).

**Оговорка к сравнению контролей.** Число сделок между режимами различается (448 / 537 / ~480),
потому что смена направления меняет длительность удержания, а значит и то, сколько последующих
сигналов будет пропущено из-за уже открытой позиции. Сравнивать поэтому корректно средний R и
t-статистику, а не абсолютную прибыль.
