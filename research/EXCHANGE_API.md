# Подключение биржи по API — как это устроено и что нужно настроить

Раздел «Своя биржа» — единственное место в приложении, где деньги настоящие.
Всё остальное (челленджи, фандед-счета, спот-портфель, инвестирование) — проп-симулятор
с виртуальным балансом. Это разделение сознательное и отражено в интерфейсе.

## Что нужно включить перед запуском

1. **Переменная окружения `EXCHANGE_ENC_KEY`** в Vercel.
   Без неё эндпоинт отвечает `503 encryption_not_configured` и подключение биржи
   недоступно — это правильное поведение: хранить ключи незашифрованными нельзя.

   Сгенерировать:
   ```bash
   node -e "console.log(require('crypto').randomBytes(32).toString('base64'))"
   ```
   Принимается 32 байта в base64 или hex, либо длинная парольная фраза
   (из неё ключ выводится через scrypt).

   **Смена этого ключа делает все сохранённые ключи бирж нечитаемыми.**
   Пользователи получат `decrypt_failed` и понятное предложение переподключить биржу.

2. **Таблица в Supabase** — выполнить `api/exchange_keys.sql`.
   RLS включён, политик нет: к таблице ходит только серверная функция под
   service-ключом. С anon-ключа из браузера таблица недоступна.

## Модель безопасности

| Угроза | Что её закрывает |
|---|---|
| Утечка дампа базы | Секреты зашифрованы AES-256-GCM, мастер-ключ в env, а не в БД |
| Перенос чужой строки себе | `user_id` входит в AAD — строка другого пользователя не расшифруется |
| Секрет в логах / ответах API | Секрет физически не выходит из серверной функции; наружу только маска `ABCD…WXYZ` |
| Секрет в браузере | Уходит один раз при подключении, поля очищаются сразу, в `localStorage` не пишется (есть тест) |
| Подмена пользователя | `user_id` берётся из токена сеанса, никогда из тела запроса |
| **Кража ключа целиком** | **Ключ с правом вывода средств не принимается — украсть можно, вывести нельзя** |

Последняя строка — главная. Всё остальное защищает от утечки; только запрет на
вывод защищает от последствий утечки. Поэтому `api/exchange.js` вызывает `probe()`
до сохранения и отклоняет ключ, у которого разрешён вывод, с объяснением.

О чём честно стоит сказать: если скомпрометирован сам сервер вместе с env,
ключи расшифровываются. Ограничение прав ключа и привязка к IP на стороне
биржи — единственное, что работает и в этом случае.

## Поддержанные биржи

| Биржа | Схема подписи | Passphrase | Проверка права вывода |
|---|---|---|---|
| Binance | HMAC-SHA256 (hex) от query, `X-MBX-APIKEY` | нет | `/sapi/v1/account/apiRestrictions` → `enableWithdrawals` |
| Bybit v5 | HMAC-SHA256 (hex) от `ts+key+recvWindow+payload` | нет | `/v5/user/query-api` → `permissions.Withdraw` |
| OKX v5 | HMAC-SHA256 (base64) от `ts+METHOD+path+body` | **да** | `/api/v5/account/config` → `perm` содержит `withdraw` |

Подпись Binance проверена в тестах против **эталонного примера из официальной
документации** — совпадает побайтово. Подписи Bybit и OKX проверены на том, что
считаются от правильного материала (в частности, у Bybit — от тела POST-запроса).

Добавить биржу = добавить объект в `ADAPTERS` в `api/_exchanges.js` с методами
`probe / balances / positions / order`. Больше нигде править не нужно.

OKX не сообщает, ограничен ли ключ по IP, — адаптер возвращает `null`, и интерфейс
не показывает про IP ничего, вместо того чтобы соврать «не ограничен».

## Чего здесь нет и почему

**Автоторговли реальным балансом нет.** Это не упущение.

Движок сигналов приложения честно измерен на истории (`research/MIE_BACKTEST.md`):
448 сделок, винрейт 45,5%, средний R −0,169 при t = −3,44. На тех же точках входа
случайная сторона даёт ≈ −0,03R, то есть движок выбирает направление **значимо хуже
монетки**. Подключить его к реальным деньгам — это не функция, а способ гарантированно
слить счёт пользователя.

Технически запрет реализован в двух местах: флаг `AUTO_TRADE_FORBIDDEN` в
`api/exchange.js` отклоняет любой ордер с `auto:true`, а на клиенте автотрейдер
физически не знает про этот эндпоинт. Ручные ордера разрешены: решение принимает человек.

Если когда-нибудь найдётся сетап с положительным матожиданием **на отложенной выборке,
не участвовавшей в подборе**, — снять запрет будет одной строкой. До тех пор он стоит.

## Эндпоинт

```
GET  /api/exchange?action=catalog     список бирж (без авторизации)
GET  /api/exchange?action=status      что подключено у пользователя
POST /api/exchange  {action:'connect', exchange, apiKey, apiSecret, passphrase?}
POST /api/exchange  {action:'disconnect', exchange}
POST /api/exchange  {action:'balances',  exchange}
POST /api/exchange  {action:'positions', exchange}
POST /api/exchange  {action:'order', exchange, symbol, side, type, qty, price?, reduceOnly?}
```

Все, кроме `catalog`, требуют `Authorization: Bearer <session token>`.

Коды ошибок, которые интерфейс показывает пользователю дословно, потому что они
содержательные: `withdrawal_enabled`, `no_trade_permission`, `key_rejected`,
`encryption_not_configured`, `decrypt_failed`, `auto_trade_forbidden`.

- «ключ и секрет НЕ сохранены в localStorage» — реальная проверка через браузер
