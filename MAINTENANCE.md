# Технические работы

Проп-фирму и Telegram-бота можно останавливать **по отдельности**: обновление
терминала не обязано затыкать бота, а профилактика бота не обязана закрывать
людям доступ к их счетам.

## Что нужно сделать один раз

1. **Таблица `app_settings`** — уже создана в Supabase (миграция
   `app_settings_maintenance`). Для нового окружения выполните
   `api/app_settings.sql`.
2. **Переменные** в Vercel → Settings → Environment Variables:

```
SUPABASE_URL=...
SUPABASE_SERVICE_KEY=...
TELEGRAM_BOT_TOKEN=...     # обязателен: по нему проверяется подпись владельца
ADMIN_TG_ID=566501781      # необязателен: по умолчанию тот же ID
```

`TELEGRAM_BOT_TOKEN` теперь обязателен для админки. Без него проверить подпись
нечем, и сервер закрывает доступ — отсутствие возможности проверить не то же
самое, что успешная проверка.

## Как пользоваться

Мини-приложение → иконка щита в правом верхнем углу → раздел **Техническое
обслуживание**. Две карточки, у каждой свой переключатель, свой текст для
пользователей и своё время окончания.

### Проп-фирма

Включено:

- пользователи видят экран техработ вместо приложения;
- `POST /api/payments {action:'create'}` отвечает `503` — новая оплата не создаётся
  даже из старой вкладки или повторённого запроса;
- **вы как владелец продолжаете видеть приложение** и можете платить и проверять оплаты.

### Telegram-бот

Включено:

- `/api/notify` не пишет пользователям (возвращает `{ok:false, skipped:'bot_maintenance'}`);
- копии важных событий владельцу приходят по-прежнему, с пометкой, что пользователю
  не отправлено — вы не теряете картину происходящего, пока бот молчит;
- само приложение работает как обычно.

## API

```
GET  /api/config
     -> { prop:{maintenance,message,until}, bot:{...}, maintenance, message, until }

POST /api/config
     { admin:<tgId>, scope:'prop'|'bot', maintenance:true, message:'...', until:'...' }
```

Плоские поля `maintenance/message/until` в ответе — зеркало контура `prop`.
Они нужны для совместимости: ответ кэшируется на 15 секунд, и у части
пользователей ещё живёт предыдущая версия `index.html`, которая читает
только их. По той же причине `POST` без `scope` трактуется как `prop`.

Ошибка записи возвращает `500` с текстом причины, а не тихое `ok`. Это
сделано намеренно: молчаливый сбой здесь означал бы, что работы «объявлены»
только на экране администратора, а люди в это время продолжают торговать.

## Тесты

```
node api/_settings.test.mjs
```

Проверяет независимость контуров, совместимость со старым форматом
и то, что ошибка сохранения действительно доходит до администратора.


## Как проверяются права владельца

Раньше админские эндпоинты доверяли полю, которое присылал клиент:

```
GET  /api/admin?admin=566501781
POST /api/payments {action:'review', admin:'566501781', decision:'approved'}
```

Этот ID — публичная константа в `index.html` в публичном репозитории. То есть
любой, кто открыл исходник, мог читать выручку и список пользователей,
**подтверждать чужие оплаты** и включать режим обслуживания. Идентификатор
говорит, кем пользователь себя называет, и ничего не доказывает.

Теперь права проверяются подписью Telegram `initData`: Telegram подписывает её
HMAC-ключом, производным от токена бота, токен живёт только на сервере, поэтому
подделать подпись нельзя. Проверяются подпись, срок жизни (24 часа, защита от
повтора) и совпадение идентификатора из **подписанных** данных с владельцем.
Сравнение хешей — постоянного времени.

Закрыты: `/api/config` (POST), `/api/admin`, `/api/payments` (список и review),
`/api/nexus` (admin_credit).

Проверка: `node api/_telegram.test.mjs` — 19 проверок, включая подделку данных
под чужой подписью, просроченную подпись и ровно ту атаку, которая работала
раньше.
